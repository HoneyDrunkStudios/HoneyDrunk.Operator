> Grid. Fill every section. Write the completed proposal to
> `/staging/status-proposal-{repo}-{YYYY-MM-DD}.md`.

## Evidence Checklist

Prerequisites for the proposed transition, verified against
`/policies/status-transition-rules.md`:

### Awake → Wiring

- [ ] README.md exists with basic project description
- [ ] Basic directory structure is in place
- [ ] Hive catalog entry exists for this Node

### Wiring → Live

- [ ] Full README.md with purpose, structure, usage, and status sections
- [ ] `/docs` directory with required documentation
- [ ] `/contracts` directory with applicable contracts
- [ ] `/policies` directory with applicable policies (or inherits from parent)
- [ ] Hive catalog entry is complete and accurate (no ERROR-level drift)
- [ ] No open ERROR-level drift findings
- [ ] CI/CD pipeline is configured and passing (if applicable)
- [ ] License file is present and correct

### Live → Wiring (Regression)

- [ ] Required documentation is missing or critically stale
- [ ] Contracts are broken or removed
- [ ] ERROR-level drift has been detected and unresolved
- [ ] Structure no longer meets Live requirements

## Rollback Plan

If the status transition causes issues or is premature:

1. **Revert the Hive catalog entry** to the previous status value.
2. **Close or revert** any PRs that were created based on the new status.
3. **Emit a Signal to Pulse** indicating the status was rolled back, with
   the reason.
4. **Create a follow-up drift report** to assess what prerequisites are still
   missing.

| Step | Action | Owner |
|---|---|---|
| 1 | Revert Hive catalog status field | {Human / Operator} |
| 2 | Close dependent PRs | {Human / Operator} |
| 3 | Emit rollback Signal | Operator |
| 4 | Re-run Drift Sentinel | Operator |
